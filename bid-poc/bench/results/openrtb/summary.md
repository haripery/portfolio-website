#### Open loop at fixed offered rates, per-request timeout 100ms (the exchange's tmax): what an exchange would see

oha sends at the offered rate on 500 connections. A request that gets no response within 100ms of being **sent** is a client timeout, which an exchange treats as no bid. When all connections are busy, a request first **waits inside oha** before it is sent; the latency percentiles include that wait (`--latency-correction`, which corrects for coordinated omission), so they are the stricter measure: under overload, "answered" requests can still be far later than 100ms from the exchange's point of view.
